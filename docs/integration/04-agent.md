# 4. agent 生命周期

`nfagent` 装在**能访问你要暴露的服务**的那台机器上（不是中继上）。它只做**出站**
连接，不需要任何入站端口、不需要任何 capability。

## 4.1 入网

```bash
# 1) 在控制台（或用 API）签一枚入网令牌
curl -s -b jar -H "X-NFR-CSRF: $CSRF" -H 'Origin: http://127.0.0.1:9443' \
  -X POST -d '{"ttl_seconds":900,"note":"home"}' \
  http://127.0.0.1:9443/api/enrol-tokens

# 2) 在内网那台机器上跑（控制台会给出可直接复制的完整命令）
nfagent -relay <中继公网地址>:8443 \
        -pin <SPKI 指纹 base64> \
        -token nf_enrol_xxxxx \
        -state-dir /var/lib/nfagent
```

- **令牌是一次性的**，默认 TTL 15 分钟。用过再用得到不可重试的 `auth_failed`。
- **agent ID 派生自令牌哈希** —— 换一枚令牌就是一个新 agent。
- `-pin` 强制必填，**没有「跳过证书校验」的选项**。指纹钉的是公钥（SPKI）
  而不是整张证书，所以中继证书续期不会打断绑定。
- `-l2-port`（默认 **443**）是承载回退端口。UDP 拨不通时 agent 会退到
  **L2 = TLS/TCP + smux**，地址用与 `-relay` **同一个主机**、端口换成这个值 ——
  因为中继的 L2 承载与共享入口共用那个端口（靠 ALPN 区分）。
  设 `0` 关闭回退。

### 承载回退：什么时候会发生，以及它的代价

出口完全封锁 UDP 的网络（工厂、企业网常见只放行 TCP 80/443）里 L0/QUIC 拨不通，
agent 会在 1.5 秒之后改试 L2。两件事必须知道：

1. **L2 上 UDP 隧道不可用。** smux 只有可靠有序流。中继会把那些隧道标成
   `degraded`，原因写「代理端承载不支持不可靠数据报」。
   **不会**把数据报塞进可靠流去假装能用 —— 那样得到的是调不掉的队头阻塞。
2. **回退是按梯级优先，不是并发竞速。** L2 在近距离网络里常比 QUIC 快，
   竞速会让网络完全正常的部署也跑在 L2 上，于是 UDP 隧道静默全挂。
   所以先给 L0 一段独占时间（1.5 秒）。代价是真被封 UDP 的网络里
   每次重连多花那 1.5 秒。

agent 的启动日志会打出当前梯级（`承载=L0/QUIC` 或 `承载=L2/TLS:443`），
走降级路径时额外打一条 WARN。中继侧看 `/api/snapshot` 的
`shared.carrier_alpn`（有几条连接走 L2）与 agent 的 `supports_datagram`。

## 4.2 状态目录：这一节决定它能不能重启

中继在首次入网时下发一把长期密钥。agent 把它连同一个机器标识落在状态目录里。

```
/var/lib/nfagent/
├── credential.json   0600   {"v":1,"agent_id":...,"key":<hex>,"issued_at":...}
├── machine_id        0600   32 位小写 hex，写一次之后只读
└── (目录本身 0700)
```

默认路径按平台：

| 平台 | 候选（按优先级） |
|---|---|
| Linux / BSD | `/var/lib/nfagent` → `$XDG_STATE_HOME/nfagent` → `$HOME/.local/state/nfagent` |
| macOS | `/Library/Application Support/nomifun/agent` → `~/Library/...` |
| Windows | `%ProgramData%\nomifun\agent\state` → `%LOCALAPPDATA%\...` |

挑选规则里有一条不显然但很要紧的：**先挑「已经有 credential.json 的那个候选」**，
再挑「第一个可创建且可写的」。否则「先以 root 跑过一次、后来改成普通用户跑」
会落到 `$HOME` 下并**重新入网** —— 中继上凭空多一个 agent，原 agent 名下的隧道
全部悬空，而两次启动的命令行一模一样。症状是「隧道一条都没了」。

`-state-dir` 显式指定时**不可用即失败**，绝不静默换目录（同上理由）。

> **坑：OpenWrt 的 `/var` 是指向 `/tmp` 的符号链接（tmpfs）。**
> 默认路径在路由器上**重启即清空** —— 落盘等于没做，而且更难查：日志会说
> 「已落盘」。**agent 自己**会检测到（用 `EvalSymlinks` 判断状态目录是否落在 `/tmp`、`/dev/shm`、`/run` 下）并在**它自己的** stderr / journal 里打一条 WARN ——中继与控制台看不到这条。解法是 `-state-dir /etc/nfagent`
> （JFFS2 overlay，写入只发生在首次入网，不存在闪存磨损问题）。

写入策略是「临时文件 → fsync → rename → **fsync 父目录**」。最后一步是必需的：
少了它，掉电后 rename 本身可能整个丢掉，于是出现「入网成功过、日志也打了、
但重启后文件不存在」的幽灵版 —— 而 MIPS 路由器的正常关机方式就是拔电。

## 4.3 重启

有凭据时直接用密钥握手，**命令行给的 `-token` 会被忽略**（并打一条 WARN 说明）——
凭据优先，因为消费一枚一次性令牌会白白产生一个新身份。

要真的重新入网就先删掉 `credential.json`。注意那会换掉 agent ID，
既有隧道需要重绑（见 4.6）。

> 在某个版本之前这一节完全不存在：密钥只写在内存里。任何 `Restart=always`
> 的部署在第一次进程重启后就**永久失联**，必须人工回控制台重签令牌。

## 4.4 失败、退避与退出

退出与否**按盘上有没有凭据分叉，不按错误码分叉**：

| 处境 | 收到不可重试的拒绝 | 行为 |
|---|---|---|
| 还没入网（无凭据） | 令牌过期 / 打错 / 已用过 | **退出**，码 1。有人正盯着终端做首次入网，快速失败是对的。 |
| 已入网（有凭据） | 凭据被撤销 **或** 中继换了库/恢复了旧备份 | **绝不退出**，持续退避重试。 |

第二格的理由：那两种情况在线上回同一个 `revoked`（存储层把「查不到」与
「已撤销」合并成同一个否定），根本分不开，而后者是**瞬时**的 —— 中继修好库、
agent 就该自动接回。

这正是 frp 的 `LoginFailExit` 修不对的地方：它让一个有凭据的服务因一次瞬时状况而退出。

多中继候选（`-relay a,b,c`）在连续失败若干次后切换到下一个。

## 4.5 本地目标策略（SSRF 防线）

agent 对**本地目标**保留一票否决 —— 否则一个被攻陷的控制台就是你内网与云元数据的跳板。

- 默认放行回环与私有段，云元数据地址**永久黑名单**。
- `-allow` 追加网段。
- **两道校验**：配置期预检只判 IP 字面量（主机名一律放过），
  拨号期**校验已解析到的地址**。后者防的是 DNS 重绑定 —— DNS 可以在预检之后
  改变解析结果。
- 所以一条「已被接受」的隧道完全可能在每次拨号时被拒。那条路会产生
  `tunnel.stream_denied` 事件，否则你看到的只是一条不通的隧道
  （那正是 frp 让人无从下手的老毛病）。

## 4.6 隧道重绑

agent ID 变了（重签令牌）之后，既有隧道的 `agent_id` 指向一个不存在的 agent，
状态报 `degraded`「代理端不在线」。

恢复方式：**把隧道的 `agent_id` 清空**。中继会在恰好一个 agent 在线时自动绑上并
回写数据库。不需要去查新的 agent ID。

> **⚠ PUT 是整体替换，不是部分更新。** 请求体里没写的字段会被写成**零值并落库**。
> 特别是 `listen_port`：漏写它会被清零，而下一次 ApplyTunnels 会给这条隧道
> **换一个内核随机端口**并回写 —— `exposure=port` 的客户端（端口写在固件里的设备）
> 会全部失联。实测确认过。
>
> 所以正确做法是**先 GET、改一个字段、再整份 PUT 回去**：

```bash
ID=t-xxxxxxxxxxxx
curl -s -b jar "http://127.0.0.1:9443/api/tunnels/$ID" \
  | jq '.agent_id = ""' \
  | curl -s -b jar -H 'Content-Type: application/json' \
      -H "X-NFR-CSRF: $CSRF" -H 'Origin: http://127.0.0.1:9443' \
      -X PUT --data-binary @- "http://127.0.0.1:9443/api/tunnels/$ID"
```

（GET 回来的对象含 `state` 等只读字段，PUT 回去是安全的 —— 服务端会忽略/重算它们。
但**不要**手工拼一个只有几个字段的请求体。）

有 2 个及以上 agent 在线时中继无法判断你的意图，会把隧道状态设为 `error`
并说明「有 N 个代理端在线，请显式指定一个」。

## 4.7 目标平台

`nfagent` 与 `nfrelay` 的可构建平台**不同**：`modernc.org/sqlite` 没有 MIPS 移植，
所以 MIPS 路由器上只能构建 agent。`make check` 会用 `go list -deps` 断言
agent 代码不依赖存储层 —— 这正是出两个二进制而不是一个带子命令的原因。

## 4.8 agent 自报的计数器

agent 每 5 秒走控制流上报一份计数器（`TypeMetrics`）。它们在控制台上与中继侧的
数字**分开显示**，因为中继只看得见自己那一侧，而下面这一整类它完全不知道：

拨本地目标失败、被本地策略否决、回向发送队列满、回向超限、回向分片重组失败。

症状是「下行统计都对，就是收不到回包」。界面上还会标出「上报是不是卡住了」——
一份十分钟前的数不该被当成现在的。
