# 9. 已知缺口

这一章是这份文档存在的主要理由。它分三类，请分清：

- **缺口** —— 想做但还没做。
- **刻意的设计决定** —— 看起来像缺陷，其实是权衡过的选择。**请不要「修」它们**，
  先读理由。
- **已知代价** —— 某个决定的副作用，暂时接受。

`README.md` 的「诚实清单」是更完整的一份（含中继内部的项）；这里只列**对接方会碰到**的。

本章若干条断言可以自己复核 —— `scripts/verify/` 下的脚本会真起 `nfrelay` + `nfagent`
打真流量，见 [`scripts/verify/README.md`](../../scripts/verify/README.md)。

## 9.1 缺口

### 没有 API 令牌 / 分权

服务间集成拿到的是那把唯一的管理员口令。同一个会话还能删掉全部隧道、下载支持包。
没有角色、没有只读凭据。会话 12 小时硬过期，无滑动续期、无 refresh 端点。

**影响**：把中继凭据放进你的 CI 或应用配置时，你放进去的是完整管理权。

### 没有 `openapi.json`

规格 §8.5（`make openapi` / `make api-diff` / `make gen-api-types`）把它规定成
「供第三方与 CLI 消费」并要求一个漂移门禁，三个 make 目标都不存在。当前唯一的端点清单是本文档与手写的 `web/src/api/client.ts`
（后者曾经漂过：调过三个后端从未注册的端点）。

### 没有 Prometheus `/metrics`

有 SSE、`/api/settings`、支持包、逐跳探测，但没有拉取式指标出口。
代码注释里以现在时提到 `nf_*` 指标名，而 `go.mod` 里没有
`prometheus/client_golang` —— 那些注释是设计意图，不是现状。

### 数据库没有恢复路径

`store.Backup` 有实现、有测试，**零调用入口**。备份要带外做
（`sqlite3 relay.db "VACUUM INTO ..."`）。恢复完全靠你自己把文件放回去。
旧二进制打开新 schema 的库时迁移会静默 no-op，没有护栏。

### SSE 没有历史与补发

`Last-Event-ID` 被**完全忽略** —— `sse.go` 里有一个 `lastEventID()` 解析函数，
但它是死代码（`sse.go:354` 的 `var _ = lastEventID` 是它唯一的引用，
存在只为压住「未使用」报错）。处理器既不读这个头，也不记日志。
所以断线重连会**静默**丢掉断开期间的事件；刷新页面会清空会话网格。

### 学习模式：已交付，但有两条固有局限

不再是缺口。三个端点与面板都在：`GET /api/tunnels/{id}/learned-sources`、
`POST /api/tunnels/{id}:apply-learned`、`POST /api/tunnels/{id}:decline-learned`，
界面在隧道详情页的「配置」页签。观测点挂在三条路径上（裸端口 TCP 的会话、
共享入口的每个请求、UDP 的每条新流），且**只记被放行之后的流量**。

两条局限是设计取舍，不是没做完：

1. **观测只在内存里，中继重启即清空。** 这些是运行时观测到的第三方地址，
   而库会被备份、事件表会被支持包外发 —— 落库等于把「谁在什么时候连过这台
   中继」写进一份要发给别人的文件。代价是重启后要重新攒，
   所以接口回一个 `observed_from`，界面必须显示它。
2. **学习窗口里扫描器与真客户端混在一起，中继分不开。** `allow_cidrs` 为空时
   一切都被放行，撞门的人也会上榜。所以界面不提供「一键全选」，
   而是把命中次数与首见/最近摆出来，让人自己勾 —— `:apply-learned` 收到一个
   **显式的空数组**会报 `nothing_selected` 而不是当成「全选」。

另外：列表有上限（每隧道 256 条），到顶时**拒新而不是挤掉最旧**（否则一次扫描
会把运维真正在找的早期客户端全部冲走），并把 `truncated` 报到界面 ——
一份被截断的列表拿去收窄会把没上榜的真实客户端全部锁死。

### L1 与 L3 承载梯级没做（L0 与 L2 已交付）

**「封 UDP 的网络下 agent 连不上」这一条不再成立**：L2（TLS/TCP:443 + smux）
已交付，agent 在 L0 拨不通时会自动退到它（`-l2-port`，默认 443，设 0 关闭）。

还没做的两级：

- **L1（QUIC 走 443）**。只在「放行 443/udp 但封了别的 UDP 端口」这种少见
  配置下才有用，而 L2 覆盖了更常见也更严格的「UDP 全封」。
- **L3（WSS:443 + smux）**。突破的是**敌视 ALPN** 的中间盒与 MITM 代理 ——
  而 L2 恰好靠 ALPN 区分承载与业务流量，所以那种网络里 L2 会被挡住。
  代价具体：一个剥掉 ALPN、或只放行明文 HTTP Upgrade 的代理后面，
  agent 仍然接不进来。`go.mod` 里没有 `coder/websocket`。

L2 自身有一条**固有**限制（不是没做完）：smux 只有可靠有序流，
所以那一级上 UDP 隧道不可用。中继会把它们标成 `degraded` 并写明
「代理端承载不支持不可靠数据报」，判别器的 `carrier_alpn` 计数则告诉你
有几条连接走在这条降级路径上 —— 那两个信号合起来解释「为什么 UDP 不通」。

### 首启窗口没有保护

`POST /api/setup` 未鉴权，谁先到谁是管理员。限速把尝试速率压住了，
但挡不住「中继起来了而运维还没去初始化」这段窗口。

### 丢包率没有测量点

`store.Sample.LossPPM` 只被写进 SQLite 再读出来，从没被赋过非零值。
界面上一律显示「—」而不是 0（0 会被读成「测过，是零」）——
详情页的实时格、隧道列表那一列、历史表的丢包列**三处都是**。
（此前后两处渲染 `0%`，那正是这一条想避免的读法。）

**数据报 MTU 不在这一条里了**：它已经被反应式学到、一直在影响分片决策，
现在也进了 `TunnelStatus.dgram_mtu`（快照与 SSE 都带它）。
缺席 / 0 表示「还没学到」—— 它是反应式的，只有在一次超限之后才有值。
承载 RTT 分位数同样有。

### 共享入口上的限额语义与独立监听器有三处不同

`max_conns`、`max_conns_per_ip`、`bytes_per_second` **在共享入口上已经生效**
（此前这三项只对 `exposure=port` 的独立监听器生效，而创建向导照常提供输入框、
详情页照常显示「已设置」—— 现象是「我给这条公网隧道配了 1 Mbps，它照样跑满」）。

三处不同必须知道：

1. **`max_conns` 在网关（HTTP）路径上算的是「并发在飞请求」，不是并发连接。**
   共享入口上一条 keep-alive 连接可以服务任意多个请求、还可以中途换隧道
   （换 Host），所以按连接算的归属必然是错的 —— 本仓已经因为「连接级判断
   约束请求级路由」修过两个真实绕过。协议升级（WebSocket）之后连接不再是
   HTTP、也就不可能再换隧道，于是那一整段自然算作同一条在飞请求。
   SNI 直通与明文兜底的 splice 路径没有这个问题（隧道固定），那里按**连接**算，
   语义与独立监听器完全一致。
2. **`max_conns: 0` 在共享入口上是「不设每隧道上限」**，兜底的是共享端口自己的
   并发上限（`DefaultMaxConns` = 512，判别器级、所有隧道共享）；
   而独立监听器上 0 是「这条隧道 512」。
3. **`packets_per_second` 在共享入口上不生效**（理由见下一条：它在 TCP/HTTP 上
   没有诚实的含义）。**刻意不在校验层报错** —— Validate 跑在每一次 PutTunnel 上，
   加一条拒绝会让已经配过这个字段的既有隧道从此存不进去。

被拒的次数分四个计数器报在 `/api/snapshot` 的 `shared` 段里：
`gateway_denied_max_conns` / `gateway_denied_per_ip`（请求级）与
`splice_denied_max_conns` / `splice_denied_per_ip`（连接级）。
它们与判别器的 `at_capacity` 是不同的量：那个是整个共享端口的上限
（保护中继不被压垮），这四个是单条隧道的配额（保护别的隧道与别的来源）。

### 改限额时哪些会掐断在飞连接

- **带宽（`bytes_per_second`）原地改，不掉线** —— 两种 exposure 都是。
- **`max_conns` / `max_conns_per_ip` 会重建 `exposure=port` 的入口监听器**，
  掐断那条隧道上所有在飞连接。信号量容量无法原地改，只能重建。
- 共享入口上两者都是下一个请求/连接生效，不影响在飞的。

> 此前**改任何一项都要重启进程才生效**（`ApplyTunnels` 对已存在的入口直接跳过，
> 而限速器固化在构造期），而 `entry.go` 的注释声称「改限速值走重建入口」——
> 那句话当时是假的。现在它是真的了。

### `packets_per_second` 在 TCP 上限的是「每次 read」而不是「包」

TCP 路径的限速器对每一次底层 `Read` 只申请 1 个「包」额度，与实际读到多少字节无关。
所以 `packets_per_second: 100` 在 TCP 上等于「每秒最多 100 次读」，吞吐会被压到
远低于 `bytes_per_second` 指定的值。

这个字段的设计目标是 UDP 的小包洪水；**TCP 隧道上不要配它**。

### `exposure=private` 是死枚举

Validate 放行它，但没有任何数据面实现：**一个监听器都不会建**，
而状态显示 `active`（绿点）、总览计入 TunnelsUp。任何客户端都是 connection refused。

控制台向导造不出这个组合，只有直接调 API 或用声明式配置会踩到。**不要用它。**

### `exposure=port` 时 `tls` 轴被完全忽略

`exposure=port` + `tls=gateway` 被 Validate 放行，但独立监听器做的是纯裸 TCP
拼接 —— 不做 TLS 握手、一个字节都不解析。而控制台会把端点渲染成
`https://<中继IP>:<port>`，暴露面摘要里「应用层鉴权」显示「已配置」。

浏览器打开那个 `https` 地址会报 `ERR_SSL_PROTOCOL_ERROR`。
**要 TLS 终止只能用 `exposure=shared`。**

### `kind` 轴在数据面一次都没被读过

`service` 与 `reverse` 的转发行为完全相同。这个字段目前只影响控制台的展示与
向导的措辞。

## 9.2 刻意的设计决定

### 所有隧道都必须有 agent；「中继自己拨号」没有实现

三个入口（TCP、网关、UDP）都调 `SessionFor(t.AgentID)`，返回 false 就放弃，
没有任何回落。未绑定的隧道会在恰好一个 agent 在线时自动绑上。

**为什么不做**：中继侧必须自己实现与 agent 同一套目标策略（默认拒绝 + 云元数据
黑名单 + 每次拨号校验已解析地址），否则 SSRF 防线在那里是缺失的 ——
而一个被攻陷的控制台就成了内网跳板。

> 这条此前是一个**更坏**的形态：四处注释与判据断言那条路径存在，
> 于是 reverse 隧道恒报 `active`（绿点），而每一个连接都被静默关掉。

### 共享入口只宣告 HTTP/1.1，不宣告 h2

WebSocket 升级需要 `ResponseWriter` 支持 Hijack，而 h2 的不支持。
而 WebSocket 穿透是本产品的核心场景之一。

### 不读 `X-Forwarded-For`（控制台限速）

数据面把 XFF/XFP 当作不可配置的安全不变量在剥。控制台再立一个「信任这个请求头」
的开关，仓库里就会有两个互相矛盾的信任锚。

**代价**：反代形态下所有请求共用一个限速桶。

### 登录限速没有独立的全局桶

全局桶能挡「一千个 IP 各试一次」的分布式爆破，但它同时是一个**锁死管理员**的开关
（攻击者打满全局桶，你连一次尝试都发不出去）。per-IP 已覆盖两种真实部署形态。

**代价**：直接暴露的形态下分布式爆破绕得过去。

### TCP 限速表现为「变慢」而不是「丢弃」

字节流丢掉中间一段就是把连接搞坏，所以 TCP 路径**等**而不丢，反压自然传播到
发送方窗口。「超限速被丢弃」这一格因此**只在 UDP 隧道上渲染** ——
TCP 隧道上它根本不显示（`web/src/pages/TunnelDetail.tsx` 的 `l4 === 'udp'` 闸门），
而不是显示成一个恒为 0 的数字。那是正确的，不是没接上。

### 拒绝 RFC 6062 的 TURN TCP 分配

`pion` 给那条路径加了 `SO_REUSEADDR + SO_REUSEPORT`，而客户端能影响
`RequestedPort` —— 两个不同客户端的分配会共用同一个中继端口，入向连接被内核
随机派给其中一个。

WebRTC 从不请求它（浏览器的「TURN over TCP」指的是**客户端腿**走 TCP，
与分配的传输协议无关），所以拒绝它不减少任何真实能力。

### 没有 DNS-01，所以通配域名拿不到 ACME 证书

签发闸门只认**逐字**注册过的域名。通配回落会让 `*.example.com` 下的任意子域
都成为可签发目标，而那正好是被滥用的形状。

家庭/工厂部署多数没有 DNS API 权限；给了凭据又过期时现象会是「证书签不出来」
而不是「DNS 认证失败」。**转发不受影响**，通配照旧生效。

### HSTS 只在声明了前置反代时下发

不是缺口，是条件行为，写在这里是因为它容易被误以为「从不下发」。

声明了 `-console-behind-tls-proxy` 时每个响应都带
`Strict-Transport-Security: max-age=31536000`；默认的明文 loopback 形态不带
（按 RFC 6797 §8.1 它在明文传输上本来就会被忽略）。

**开那个 flag 之前要想清楚**：HSTS 是唯一服务端**撤销不回来**的头
（浏览器侧粘着 max-age）。一年期意味着这个主机名此后一整年只能走 HTTPS ——
想改回明文访问会发现浏览器不让。

### 控制台不能挂在反代子路径下

见 [2.5](02-deployment.md#25-控制台挂不到反代子路径下)。

## 9.3 已知代价

| 代价 | 量级 |
|---|---|
| 成功登录会清掉该源 IP 的失败预算，所以反代后面与你同源的攻击者会在你每次登录后拿到新的突发额度 | 你一天登录 5 次 = 攻击者多 50 次，而基线本来就有 2880 次/天 |
| argon2 并发闸把峰值内存压到约 128 MiB，代价是洪水期间正常登录可能排队到超时（503） | 修之前 120 个匿名请求峰值 **5598 MiB**，现在 350 MiB |
| 内置 TURN 只绑 udp4/tcp4 | IPv6-only / 464XLAT 网络的客户端**连不上** TURN |
| 发布签名的公钥是占位、私钥不存在 | `make verify` 与 `install.sh` 对任何真实发布必然失败。要用先 `make keygen` 换掉公钥 |
| 单租户，`tenant_id` 列已保留 | 但 `admins` 与 `console_sessions` 两张表**没有**这一列，真做多租户必须迁移它们 |
